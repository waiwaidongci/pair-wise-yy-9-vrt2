# 古法蓝晒底片整理室

运行：

```bash
npm start        # 访问 http://localhost:3040
npm test         # 工序规则测试
```

数据保存在 `data/cyanotype-negative-room.json`。

## 标准工序

每张底片建档时自动生成六个按顺序执行的待执行项：

**涂布 → 晾干 → 曝光 → 冲洗 → 复晒 → 入盒**

- 每次只轮到一步：只有当前工序可以提交，后面的步骤不能越过它完成。
- 某步提交失败必须填写原因，工序停在原处；返工通过后才能继续后续步骤。
- 每步保留全部提交历史（通过/失败、时间、是否返工、备注），失败原因和返工记录在页面可见。
- 底片状态完全由工序进度派生：`待涂布 / 待晾干 / 待曝光 / 待冲洗 / 待复晒 / 待入盒 / 待交付 / 已交付`。
- 六道全部通过（入盒完成）后显示「待交付」，执行交付后流程结束。
- 旧底片在服务首次加载时自动补录当前进度：按历史步骤记录推断，旧状态（待曝光/冲洗中/待入盒等）只作兜底。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `server.js` | HTTP 入口，只负责启动服务 |
| `src/store.js` | 数据存取层：JSON 文件加载、落盘、增查、旧档迁移 |
| `src/workflow.js` | 工序规则层：工序定义、顺序提交、失败返工、状态派生、旧档补录（纯逻辑，无 IO） |
| `src/routes.js` | 接口路由层：HTTP 解析、参数校验、错误码映射 |
| `src/view.js` | 操作室页面渲染 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/items` | 底片列表（含每步状态、失败原因、返工记录） |
| `POST` | `/api/items` | 建档，自动生成六个待执行项（body 需含 `code`） |
| `POST` | `/api/items/:id/workflow/:stepKey` | 提交当前工序，body：`{ "result": "pass"\|"fail", "note": "..." }`；`fail` 时 `note` 必填 |
| `POST` | `/api/items/:id/deliver` | 六道全部通过后交付 |
| `GET` | `/api/stats` | 按派生状态统计，另附 `reworking`（有工序失败待返工的底片数） |

越步提交、未完成即交付、已完成重复提交等返回 409；缺编号、缺失败原因等返回 400。
